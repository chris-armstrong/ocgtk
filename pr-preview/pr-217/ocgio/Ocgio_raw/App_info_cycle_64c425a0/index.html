The layer 1 modules of Ocgio.Raw.App_info, Ocgio.Raw.App_launch_context, Ocgio.Raw.Drive, Ocgio.Raw.File, Ocgio.Raw.File_enumerator, Ocgio.Raw.File_monitor, Ocgio.Raw.Mount, Ocgio.Raw.Volume, defined together because they refer to each other. Each has a module of its own that re-exports it; use that module rather than this one.

module App_info : sig ... end

Information about an installed application and methods to launch it (with file arguments).

module App_launch_context : sig ... end

Integrating the launch with the launching application. This is used to handle for instance startup notification and launching the new application on the same screen as the launching window.

module Drive : sig ... end

GDrive represents a piece of hardware connected to the machine. It’s generally only created for removable hardware or hardware with removable media. For example, an optical disc drive, or a USB flash drive.

module File : sig ... end

GFile is a high level abstraction for manipulating files on a virtual file system. GFiles are lightweight, immutable objects that do no I/O upon creation. It is necessary to understand that GFile objects do not represent files, merely an identifier for a file. All file content I/O is implemented as streaming operations (see Gio.InputStream and Gio.OutputStream).

module File_enumerator : sig ... end

GFileEnumerator allows you to operate on a set of Gio.File objects, returning a Gio.FileInfo structure for each file enumerated (e.g. Gio.File.enumerate_children will return a GFileEnumerator for each of the children within a directory).

module File_monitor : sig ... end

Monitors a file or directory for changes.

module Mount : sig ... end

The GMount interface represents a user-visible mount, such as a mounted file system.

module Volume : sig ... end

The GVolume interface represents user-visible objects that can be mounted. For example, a file system partition on a USB flash drive, or an optical disc inserted into a disc drive.
